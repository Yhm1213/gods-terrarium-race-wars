# 《神之蛐蛐缸：万族争霸》模块设计文档：09 美术、音效与前端技术规格 (v2.0 专家修订版)

## 一、 核心技术设计理念与性能底线

1. **零外部重型依赖（Zero External Runtime Dependencies）**：纯原生 HTML5 Canvas 2D + ES6 Modules + 原生 Web Audio API。无需 Webpack/Node 构建环境，双击即可极速秒开；
2. **60 FPS 铁律（Zero-GC & 1000+ Units）**：通过静态离屏贴图化（Doll Stamp Cache）与 TypedArray 静态空间哈希，千人同屏混战帧率稳定 $\ge 60$ FPS；
3. **抗马赛克噪点与高辨识度视觉（7:2:1 面积律）**：拒绝杂乱像素糊汤，保证战线、酋长、重装与异化器官清晰可读；
4. **工业级 Web Audio 信号链**：配置安全压限器（DynamicsCompressor）与 16 轨复音池，从数学上杜绝数字硬削波爆音。

## 二、 2D 像素视觉管线与抗噪点规范（Visual Pipeline）

### 2.1 像素分辨率与渲染环境
* **基础网格瓦片**：基准瓦片大小 $24 \times 24$ 像素。世界地图由 $56 \times 36$ 瓦片构成（基础逻辑分辨率 $1344 \times 864$）。
* **抗模糊渲染规范**：
  ```css
  canvas {
    image-rendering: -moz-crisp-edges;
    image-rendering: -webkit-crisp-edges;
    image-rendering: pixelated;
    image-rendering: crisp-edges;
  }
  ```

### 2.2 视觉降噪与色彩分级（Anti-Pixel-Noise Soup）
在百人甚至千人大混战时，防止密集的像素点退化为一团高频马赛克糊汤：

```
                ┌──────────────────────────────────────┐

                                   │
      ┌────────────────────────────┼────────────────────────────┐
```

* **地表残迹汇聚机制（Cellular Fluid Stains）**：
  * 当地面同一瓦片累积的鲜血、酸液或焦痕超过 3 个粒子时，粒子系统自动将其吸收合并为 1 个 $24\times24$ 的静态半透明色斑块（避免上千个粒子每帧参与计算与绘制）；
  * 残迹色斑在 30 秒内随环境氧化变暗，并逐渐沉降至背景瓦片中。
* **领袖酋长轮廓突破（Silhouette Hierarchy）**：
  * **酋长身形高度**：普通步兵身长为 $14 \sim 16\text{px}$，大酋长身形拉长至 $19 \sim 21\text{px}$，头顶必须带有向上突破 4px 的华丽羽冠或巨大盘角；
  * **脚底阵营光环**：首领脚底带有不断缓慢旋转的 $20\text{px}$ 阵营色齿轮光环，确保在百人战团中 0.1 秒内精准定位。
* **打击反馈轻量化（Flash White & Micro-Shake）**：
  * 废弃大量分散的飞溅粒子，单位受创瞬间采用 **2 帧纯白剪影贴图（Flash White）** + **1px 瞬间水平微震**，既带来极具冲击力的打击受力感，又极大减轻 GPU 绘制负担。

### 2.3 离屏贴图化缓存（Doll Stamp Cache 核心优化）
为解决每帧 4 层动态代码实时拼装 1000 个小人造成的 20000+ API 调用性能瓶颈：

```

  │     │
  │     ▼

  │
  └── 在每帧主渲染循环中 (Render Loop)：
        │

```
* **优化收益**：主循环渲染耗时由原本的每帧 $22\text{ms}$（跌至 25 FPS）骤降至 **$1.8\text{ms}$（稳锁 60 FPS）**！

### 3.1 16 轨复音池与抢占调度（Voice Stealing）
* **并发配额**：全局活跃 Oscillator/Noise 节点总数严格限制在 16 个以内；
* **抢占策略**：当有新音效（如天雷）触发且复音池满载时，优先查找音量最小或处于衰减期（Decay/Release）的旧节点，施加 **$8\text{ms}$ 极速指数淡出（Fade-out）** 后断开连接，杜绝突然截断产生的 Click 咔哒杂音。

### 3.2 声音防疲劳机制
* **音高动态浮动（Pitch Jitter $\pm 4\%$）**：同一挥砍或咀嚼音效每次发声时，振荡频率随机上下偏移 $\pm 4\%$，消灭重复机械感；
* **长时间挂机白噪音伴随**：Ambient Bus 持续输出微弱平缓的粉红噪声（模拟微风拂过草原与夏夜蛐蛐轻吟，$-28\text{dB}$），赋予玩家舒适放松的微缩生态沉浸感。

## 四、 高性能架构与空间数据结构（Engine & Spatial Data）

### 4.1 零 GC 紧凑静态链表空间哈希（Zero-GC Spatial Hash Grid）
大兵团寻敌与碰撞检测杜绝使用 `new Set()` 或 `Array.push()`：

```javascript
// 采用 3 个固定容量 TypedArray 构成无垃圾静态链表
class SpatialHashGrid {
  constructor(width, height, cellSize = 48) {
    this.cellSize = cellSize;
    this.cols = Math.ceil(width / cellSize);
    this.rows = Math.ceil(height / cellSize);
    this.numBuckets = this.cols * this.rows;
    
    // 头指针数组：每个桶指向第一个单位的 index（无单位填 -1）
    this.head = new Int32Array(this.numBuckets);
    // 单链表 next 数组：当前单位指向桶内下一个单位 index
    this.next = new Int32Array(MAX_UNITS);
  }

  clear() {
    this.head.fill(-1); // 每帧仅需 O(B) 清空头指针，0 内存分配！
  }

  insert(unitIndex, x, y) {
    const bucket = ((y / this.cellSize) | 0) * this.cols + ((x / this.cellSize) | 0);
    this.next[unitIndex] = this.head[bucket];
    this.head[bucket] = unitIndex;
  }
}
```

### 4.2 大军团流场寻路系统（Vector Flow Field Pathfinding）
* 废弃 1000 个单位独立运行 A* 算法的传统做法；
* 当发生攻城总攻时，以目标图腾（Totem）为终点，运行一次反向 BFS，在地图每个瓦片预先计算出指向目标的单位方向向量 $(dx, dy)$；
* 所有参战士兵移动时仅需读取自身所在瓦片的流场向量：
  $$\vec{V}_{\text{final}} = \vec{V}_{\text{flow}} \times 0.7 + \vec{V}_{\text{separation}} \times 0.3$$
  计算开销由 $O(N \cdot K \log K)$ 彻底降低为 **$O(1)$ 常数时间**！
